# RUNBU

마라톤 대회 일정, 목표 기록, 훈련과 식단을 한곳에서 확인하는 한국어 웹앱의 웹앱입니다. 메인은 회원 공용 러닝 마일리지 기록판이며, 아래 대회·신체·식사 기능은 개인 브라우저 저장 방식입니다.

## 실행

Node.js 24에서 별도 패키지 설치 없이 실행합니다.

```sh
cd /workspace/runbu
npm run dev
```

기본 포트는 3000이며 `PORT` 환경변수로 변경할 수 있습니다. 서버는 `0.0.0.0`에 바인딩합니다. 검증은 `npm test`로 실행합니다.

## 기능

- 대회 추가·수정·일정 삭제, 거리·날짜·목표 기록 저장
- 월별 달력, 목표 페이스, 다음 대회 카운트다운
- 대회까지 남은 기간에 따른 기본 훈련량 조정, 최근 레이스 이후 회복 안내
- 일일 식사·수분 가이드
- 회복 간격 경고와 가상 대회의 일정 적합성 안내
- 가상 대회명·지역 검색, 거리 및 접수 중 필터
- 지난 대회 완주 기록(시:분:초)과 메모 저장·수정·삭제
- 나의 대회 기록에서 전체 완주 내역과 거리별 필터 확인
- 메인 화면에 5K·10K·하프·풀 PB 자동 표시(초 단위 비교)
- 트랙 라인, 강조된 카운트다운, PB 카드와 간단한 진입 모션
- 모바일 레이아웃과 브라우저 localStorage 저장

처음에는 명시적으로 표시한 샘플 일정을 보여 줍니다. 첫 대회 등록 또는 ‘빈 일정으로 시작’을 누르면 개인 일정으로 전환합니다. 날짜는 한국 시간 기준입니다.

## 현재 범위

대회 검색 데이터는 모두 가상 예시이며 실제 접수·결제·취소, 공식 대회 정보 검색은 연동하지 않았습니다. 앱의 일정 삭제는 실제 대회 취소가 아닙니다. 기록은 현재 브라우저에만 저장되고 로그인·서버 동기화는 없습니다.

훈련은 기본 주간 루틴이며 운동 경력·현재 주간 거리·부상 이력에 따른 개인화는 아직 없습니다. 목표 기록은 참고 페이스로 표시합니다. 식단은 식사 예시이며 섭취량 계산이나 식사 기록 기능은 없습니다.

일정 조언은 5K 3일, 10K 7일, 하프 14일, 풀 28일의 제품용 보수적 기준입니다. 연속 대회 두 개 중 긴 기준을 적용하며 의학적으로 검증한 회복 판정이 아닙니다.

## GitHub Pages 배포

대회·신체·식사 기능은 정적 호스팅으로 사용할 수 있지만, 현재 메인의 공용 마일리지는 Node.js 서버가 필요하므로 GitHub Pages만으로는 작동하지 않습니다. 기존 정적 기능을 배포하는 방법: GitHub 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, 브랜치 **main**, 폴더 **/ (root)**를 선택하고 저장합니다. 배포 완료 후 Pages 화면에서 접속 주소를 확인합니다.

CSS와 JavaScript는 상대 경로를 사용하며 `.nojekyll`로 정적 파일을 그대로 제공합니다. 배포 후에도 실제 대회 접수는 연동되지 않고 기록은 사용 중인 브라우저에만 저장됩니다.

## 완주 기록 사용법

**나의 대회 기록 → 지난 대회 기록**에서 날짜·거리·완주 시간을 입력합니다. 기존 일정은 **수정/기록 입력**에서 완주 시간을 추가합니다. PB는 오늘까지의 실제 완주 시간만 비교하며, 목표 시간과 미래 대회 기록은 포함하지 않습니다. 기록 수정·삭제 시 PB를 다시 계산합니다. **기록 삭제**는 완주 시간과 메모만 제거하고 대회 일정은 유지합니다.

기존 `runbu-races-v1` 저장 데이터를 그대로 사용하며 새 기록은 선택 필드로 추가하므로 기존 일정은 유지됩니다. 데이터는 계속 현재 브라우저에 저장됩니다.

## Runner edition v3

- **나의 대회 기록** 맨 위의 **이전 대회 등록**에서 지난 대회를 바로 입력할 수 있습니다. 목표 기록 입력 없이 유효한 완주 기록과 과거 날짜로 등록합니다.
- **훈련 & 식단 → 나의 몸 & 식단 체크**에서 키와 날짜별 체중을 저장합니다. 같은 날짜는 덮어쓰고, 체중 이력에서 개별 삭제할 수 있습니다. 최근 체중과 첫 측정 대비 변화를 표시합니다.
- 키는 BMI 참고값에, 체중과 오늘의 훈련량은 탄수화물·단백질의 일반적인 성인 운동인 참고 범위에 사용합니다. 단백질 1.2–1.6 g/kg/일, 탄수화물은 휴식 3–4, 일반 훈련 3–5, 10km 이상 5–7 g/kg/일의 단순 안내입니다. 개인 열량·질환·운동 경력·에너지 가용성을 반영한 영양 처방이 아닙니다.
- 식사 체크는 날짜별로 이 브라우저에 저장합니다. 신체 정보는 `runbu-body-v1`, 식사 체크는 `runbu-meals-v1` 키를 사용하고 기존 일정 저장소는 유지합니다. 외부로 신체 정보를 전송하지 않습니다.
- 메인 화면의 대회 당일 날씨는 **RaceWeather 링크 + 수동 예보 저장**입니다. 해당 사이트의 API, 재사용 정책, CORS 지원을 확인하지 못해 자동 수집은 구현하지 않았습니다. 날씨는 사용자가 입력한 수치와 확인일을 표시하며 자동 갱신되지 않습니다. 예보가 없는 날짜에 수치를 만들어 표시하지 않습니다.
- 자동 연동 조사를 위해 클라우드 네트워크에 `raceweather.run` 허용 초안을 저장했습니다. 설정 적용 이후 공식 API 제공 여부부터 확인해야 합니다. 프런트엔드에 비밀 API 키를 넣지 마세요.

## Street Pace edition v4

- 메인 **나의 레이스**는 연도별로 묶습니다. 연도는 최신순이며 연도 안의 일정은 날짜순입니다.
- **레이스 캘린더** 목록은 **남은 대회 / 지나간 대회**를 나눈 후 각각 연도별로 표시합니다. 지난 날짜와 오늘 완주 기록이 있는 대회는 지난 목록에 포함합니다. 달력에서도 지난 대회와 남은 대회의 표시 색상이 다릅니다.
- 이전 대회 등록란에서 목표 기록 입력을 제거했습니다. 지난 대회 수정에서도 목표 입력을 숨기되 기존 목표 데이터는 유지합니다.
- 밝은 아이보리·라일락·코발트·오렌지 팔레트와 매거진형 연도 제목을 적용했습니다. Tracksmith와 Bandit Running 공식 페이지를 참고하려 했으나 환경의 외부 접속 제한으로 직접 열람하지 못했습니다. 해당 사이트를 열람하거나 그대로 재현한 디자인이라고 주장하지 않습니다.

## Race Day edition v5

- **대시보드 → 러닝 홈**으로 이름을 바꾸고 모든 카테고리에 같은 밝은 배경을 적용했습니다.
- 다음 대회 배너 가운데에 당일 날씨를 배치했습니다. 예시 대회에 임의의 기온을 표시하지 않습니다.
- 브라우저에서 **Open-Meteo 공개 예보 API**를 직접 요청하는 기능을 추가했습니다. RaceWeather에서 데이터를 수집하는 기능은 아닙니다. 별도 API 키는 사용하지 않으며, 도시 좌표와 조회 기간만 전송합니다. 신체 정보·기록·대회명은 날씨 제공자에게 전송하지 않습니다.
- 대회 장소에서 지원 도시명을 찾거나, 배너 **설정**에서 도시와 조회 시각(한국 시간)을 선택합니다. 도시 대표 좌표이므로 실제 코스와 차이가 있을 수 있습니다. 기본 조회 시각은 08:00입니다.
- 조회 범위는 오늘부터 15일 후까지입니다. 대회 날짜·시각과 일치하는 시간별 예보만 표시합니다. 범위를 벗어나거나 데이터가 누락된 경우 예보 없음으로 표시하며 현재 날씨를 미래 대회 날씨로 대신하지 않습니다.
- 기온·체감온도·습도·강수확률·풍속, 출처와 조회 시각을 표시합니다. 최근 결과는 세션 내 10분간 재사용하고 실패 시 재시도 버튼을 제공합니다. 새로고침 또는 재조회 시 최신 예보를 요청합니다.
- 검증: 실제 외부 요청은 현재 클라우드 네트워크 정책에서 403으로 차단됐습니다. 실제 예보 수신은 미확인 상태입니다. 모의 API 응답으로 날짜/시간 매칭, 오류·재시도, 지역 설정 유지, 모바일과 배경 통일을 검증했습니다. `node --test --test-isolation=none logic.test.js weather.test.js`로 로직 검증을 실행합니다.
- `api.open-meteo.com`을 기존 `raceweather.run` 허용 초안에 추가 저장했습니다. 이는 현재 실행 환경에 적용된 상태가 아니며, 환경 설정에서 검토·저장 및 게시한 뒤 실제 API 요청 검증을 재개할 수 있습니다. 배포된 앱은 방문자의 브라우저에서 API에 요청하므로 클라우드 작업 환경과 접속 조건이 다릅니다.
- 대회 둘러보기 목록은 여전히 명시적으로 표시한 가상 데이터입니다. 실시간 대회 접수 목록 연동과는 별개입니다.

## Night Run edition v6

- 딥그린·라임 테마를 모든 메뉴와 모바일에 동일하게 적용했습니다.
- 모바일에서는 본문 위의 별도 헤더를 숨기고 RUNBU 로고 오른쪽에 **대회 등록** 버튼을 배치했습니다. PC의 기존 헤더 등록 버튼은 유지됩니다.
- 대회 둘러보기의 가상 대회·접수 상태·날짜 데이터를 제거했습니다. 마라톤온라인(`www.marathon.pe.kr`)과 로드런(`www.roadrun.co.kr`) 링크 및 네이버 대회 검색 이동을 제공합니다. 검색어와 ‘마라톤 대회 일정 접수’ 키워드로 외부 검색을 열며, 앱이 실제 대회 목록을 수집했다고 표시하지 않습니다.
- **미완료 사항:** 실제 대회 일정 자동 수집. 두 후보 출처 모두 현재 클라우드에서 CONNECT 403으로 차단되어 최신 페이지, API, 데이터 재사용 조건을 확인하지 못했습니다. API나 파서가 존재한다고 가정하여 미검증 수집 코드를 추가하지 않았습니다.
- 기존 날씨 접속 허용 요구사항을 보존하면서 `marathon.pe.kr`, `www.marathon.pe.kr`, `roadrun.co.kr`, `www.roadrun.co.kr` 허용 초안을 저장했습니다. 환경 설정에서 검토·저장하고 게시한 뒤 실제 접근과 제공 방식 조사를 이어가야 합니다. 초안 저장은 현재 실행 환경의 접속 허용 적용과 다릅니다.
- 브라우저에서 PC/모바일 등록 버튼, 모바일 헤더 숨김, 등록 후 재접속 시 저장 유지, 모든 메뉴의 배경 및 가로 넘침을 검증했습니다. 외부 검색은 네트워크 제한 때문에 모의 응답으로 URL 이동만 검증했습니다.


## 크루 공용 마일리지 홈

회원가입·로그인 없이 바로 회원별 마일리지 그래프를 표시합니다. 박경태, 장경자, 김애진, 이시광, 홍곤표, 설미경, 도은진 7명을 사전 등록합니다. 기록할 회원을 선택해 일일 러닝 거리와 월간 목표를 입력합니다. 접속한 누구나 회원 이름을 선택해 기록과 목표를 수정할 수 있는 공용 공간입니다. 회원 선택은 본인 인증이 아닙니다.

조회 월 변경으로 월별 거리와 목표 달성률을 비교합니다. 기존 2026년 1~10월 합계·목표 70건은 각 사전 등록 회원에게 연결됩니다. 거리 공란 28건은 미입력으로 보존하며 일별 거리나 러닝 일수를 추정하지 않습니다. 기존 합계가 있는 달의 새 일별 거리는 기존 합계에 더해지므로 이미 합계에 포함된 거리를 중복 입력하지 마세요. 목표는 해당 월에 저장한 값, 과거 해당 월 목표, 최근 기존 목표 순으로 적용합니다.

Node.js 24에서 `npm start`로 실행하며 외부 패키지 설치는 없습니다. SQLite 기본 경로는 `$HOME/.local/share/runbu/crew.sqlite`이며 `RUNBU_DB_PATH`로 영속 디스크의 절대 경로를 지정할 수 있습니다. 서버 재시작 후에도 같은 DB 파일을 유지하고 백업하세요. Node.js 서버와 영속 디스크가 필요하므로 GitHub Pages만으로는 공용 기록이 작동하지 않습니다. 단일 서버 인스턴스를 사용하세요. `PORT` 기본값은 3000입니다.

기존 가입 계정과 개인 기록 테이블은 삭제하지 않지만 새 공용 화면에 자동 병합하지 않습니다. 이전 가입·로그인 API는 비활성화됐습니다. 대회·신체·식사 기능은 계속 개인 브라우저 저장 방식입니다. 사전 회원과 월간 이력은 최초 실행 시 중복 없이 추가하며 기존 DB 값을 덮어쓰지 않습니다.

`npm test`로 과거 기록, 회원 7명 등록, 월별 합계, 목표, 일별 거리 수정·삭제 및 재시작 후 데이터 보존을 검증합니다. 임시 DB의 실제 HTTP 요청으로 로그인 없는 조회·저장과 회원 ID·날짜 검증을 확인했습니다.


## Render 무료 서버 + Supabase PostgreSQL

Render Environment에 `DATABASE_URL`로 Supabase **Connect → Direct → Session pooler**의 PostgreSQL 연결 주소를 저장합니다. 비밀번호를 포함하므로 서버 환경변수로만 설정하고 프런트엔드·GitHub·채팅에 공개하지 마세요. 비밀번호의 특수문자는 URI용 퍼센트 인코딩이 필요합니다.

`DATABASE_URL`이 있으면 PostgreSQL을 선택하며 `RUNBU_DB_PATH`와 로컬 파일은 사용하지 않습니다. 연결 실패 시 SQLite로 전환하지 않고 시작을 중단하여 기록 분산·손실을 방지합니다. Render의 기존 `RUNBU_DB_PATH`는 제거해도 됩니다. `DATABASE_URL`이 없는 개인 PC는 기존 SQLite 방식으로 실행합니다. 기존 PC/서버 SQLite에 직접 입력한 신규 기록은 PostgreSQL로 자동 이전하지 않습니다.

Render Build Command는 `npm ci`, Start Command는 `npm start`, Node.js는 24로 설정합니다. 외부 PostgreSQL을 쓰면 Render 영속 디스크가 필요하지 않습니다. 최초 실행 시 `runbu` 전용 스키마에 테이블과 회원 7명·월간 이력 70건을 등록하고 기존 값은 덮어쓰지 않습니다. 앱이 만든 테이블은 RLS를 켜고 브라우저용 API 권한을 열지 않습니다. Supabase의 기본 데이터베이스 관리자 연결을 서버에서 사용하세요. 가입 없이 모든 방문자가 앱의 공용 기록 API를 사용할 수 있다는 제품 정책은 그대로입니다.

원격 PostgreSQL은 TLS와 인증서 검증을 사용합니다. 공식 연결 서버의 인증서가 기본 신뢰 저장소에 없다면 Supabase가 제공하는 공식 CA 파일을 서버에 설치하고 `PGSSLROOTCERT`에 해당 파일 경로를 설정합니다. 검증을 끄지 마세요. 연결 오류 로그에는 비밀번호·연결 주소를 출력하지 않고 오류 코드만 출력합니다.

`npm ci` 후 `npm test`에서 SQLite 및 PostgreSQL 엔진(PGlite) 저장 로직을 검증합니다. 실제 Supabase 네트워크/권한/인증 성공은 Render에서 배포 후 확인해야 합니다. 무료 서비스의 휴면·용량·연결 제한은 각 제공자의 정책을 확인하세요.
